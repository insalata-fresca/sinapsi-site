Deep dive: governance as code

From a rule to its enforcement

Governance is the binding domain of the knowledge service. It rules the platform, the applications and the Factory, and it is honest about what enforces each rule.

  1. Changed like code.Every change is a reviewed pull request, and a rule change needs a person's approval. Nothing yet binds that approval to the merged revision.
  2. A graph, not a folder.The map, the rules and the procedures are linked, so dependencies show.
  3. Served once, consumed twice.People and agents read the same records. The answers match when their permissions do.
  4. Honest labels.A rule labelled as enforced when it is not does more harm than no rule.
